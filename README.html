🤖 esp32c3_super_mini_robot-bit-rxy

ESP32-C3 differential-drive robot, controlled over Bluetooth Low Energy by the free, unmodified bit-rxy web app — joystick, D-Pad, horn, live gauges, sound feedback, and WiFi OTA updates.

ESP32-C3 bit-rxy BLE WiFi OTA

🌟 What is this?

This is a fork of esp32c3_super_mini_robot_remotexy (renamed from esp32c3_super_mini_robot; the original, still-untouched RemoteXY version) with the control layer replaced end to end — the robot now speaks the same Bluetooth protocol as a BBC micro:bit running the bit-rxy MakeCode template, so the unmodified, free web app can drive it. No paid app, no App Store review.

Everything else — servos, buzzer, NeoPixels, OLED, ultrasonic sensor, battery monitor — is unchanged from the original. This repo is the sole working directory for all further robot firmware work.

📖 Full write-up: the wiki article covers the clone/flash/test walkthrough, protocol internals, the joystick-flood BLE post-mortem, and OTA setup in more depth than this page.

🚀 Quick start

git clone https://github.com/abourdim/esp32c3_super_mini_robot-bit-rxy.git
cd esp32c3_super_mini_robot-bit-rxy/01_software/01_app
./launch.sh flash              # first flash: compile + upload over USB + monitor

Then open abourdim.github.io/bit-rxy, tap Connect, and pick diy_app_b3 (or a uBit-prefixed name) from the device chooser. The app auto-loads the robot's layout — joystick, D-Pad, horn, gauges, battery, sound — and switches to Play mode.

📡 WiFi OTA updates

After the first USB flash, every update after that can go over WiFi instead. Hold the debug button (GPIO0, also used as an in-game action button):

Hold durationResult
~3 secondsEnters OTA mode, reconnects to the last WiFi network it joined
~8 seconds (keep holding)Forgets the saved network and opens a WDIY-Robot-Setup captive portal to pick a new one

No SSID/password compiled in — WiFiManager handles storage and the setup portal. Once the OLED shows OTA ready and an IP:

cd 01_software/01_app
./ota_flash.sh <robot-ip>                       # build from source, then flash
./ota_flash.sh <robot-ip> path/to/firmware.bin   # flash an exact pre-built .bin instead

Full walkthrough (captive portal screenshots, troubleshooting): wiki article, OTA section.

Why two .pio/build/ folders? platformio.ini defines two environments — esp32-c3-devkitm-1 (USB, upload_protocol = esptool) and esp32-c3-devkitm-1-ota (WiFi, upload_protocol = espota, no serial-specific upload_flags). PlatformIO always gives each environment its own isolated build cache, even when one extends the other and only overrides a couple of settings — that's normal, not a sign anything's wrong.
